# 1C_MCP_Data

Расширение 1С:Предприятие 8.3, которое добавляет MCP-серверу [`MCP_Сервер`](https://github.com/vladimir-kharin/1c_mcp) инструменты доступа к данным информационной базы: выполнение запросов, чтение объекта по ссылке, поиск ссылок, сведения о конфигурации, проверку прав и чтение журнала регистрации.

Расширение не реализует транспорт и протокол MCP. Оно регистрирует обработки-контейнеры в подсистеме `mcp_КонтейнерыИнструментов`, которые сервер `MCP_Сервер` обнаруживает и публикует как MCP-инструменты.

## Возможности

| Инструмент | Назначение |
|---|---|
| `execute_query` | Выполняет запрос (в том числе пакет запросов) на языке запросов 1С и возвращает результат в формате `table`, `csv` или `json`; поддерживает параметры запроса и ограничение числа строк. |
| `get_object` | Читает объект по ссылке: стандартные реквизиты, реквизиты и, при необходимости, табличные части. |
| `find_references` | Ищет ссылки на объект в реквизитах, измерениях, ресурсах, стандартных реквизитах и табличных частях объектов метаданных. |
| `get_configuration_info` | Возвращает имя, синоним, версию, режим совместимости, вариант встроенного языка, версию платформы и текущего пользователя. |
| `check_rights` | Проверяет право текущего пользователя на объект метаданных. |
| `read_event_log` | Читает журнал регистрации: последние события, только ошибки, период, события, пользователи, компьютеры, объекты метаданных. |

Все инструменты только читают данные. `execute_query` работает только на языке запросов, `get_object` и `find_references` — с метаданными и данными, `get_configuration_info` — со свойствами конфигурации, `check_rights` — с правами доступа, `read_event_log` — с журналом регистрации. Инструментов записи и выполнения произвольного кода 1С в расширении нет.

## Требования

- 1С:Предприятие 8.3.20 или новее (режим совместимости расширения — `Version8_3_20`), управляемое приложение.
- Расширение `MCP_Сервер` версии 1.9.1 или новее (проверено на 1.9.1) с поддержкой поиска корневых подсистем по имени `mcp_MCPСервер`.
- Опубликованный HTTP-сервис MCP (по умолчанию `/hs/mcp`) — настраивается на стороне `MCP_Сервер`.
- Для `read_event_log` — право «Журнал регистрации» (`EventLog`) у пользователя информационной базы. Право выдаётся только основной конфигурацией; роли расширения не могут его предоставить.

## Установка

1. Скачайте готовое расширение `build/1C_MCP_Data.cfe`.
2. В Конфигураторе откройте «Расширения конфигурации», добавьте файл и примените его к базе.
3. Убедитесь, что расширение `MCP_Сервер` установлено и его HTTP-сервис доступен.
4. Назначьте пользователю публикации роли:
   - `1C_MCP_Data_ПраваИнструментЗапросы` — доступ к `execute_query`, `get_object`, `find_references`, `get_configuration_info` и `check_rights`;
   - `1C_MCP_Data_ПраваИнструментЖурналРегистрации` — доступ к `read_event_log`.

   Пользователь с полными правами (например, `admin` в тестовой базе) видит инструменты без назначения ролей.
5. Проверьте `tools/list` MCP-сервера: в списке должны появиться все шесть инструментов.

Роли расширения дают только право `Use` на обработки-контейнеры. Доступ к данным определяется правами пользователя информационной базы; `check_rights` ничего не выдаёт, а только проверяет уже назначенные права.

## Инструменты

### `execute_query`

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|---|---|---|
| `querytext` | string | да | — | Текст запроса на языке запросов 1С. Допускается пакет запросов, разделённых `;`. |
| `parameters` | object | нет | — | Параметры запроса: ключ — имя параметра без `&`. Значения: строка, число, булево, `null`, массив или типизированный объект `{"type":"date","value":"..."}` / `{"type":"ref","value":"Справочник.Номенклатура:<uuid>"}`. |
| `format` | string | нет | `table` | `table` — текстовая таблица, `csv` — значения через запятую, `json` — массив результатов с колонками и строками. |
| `maxRows` | number | нет | `1000` | Максимум строк на один результат запроса. `0` — без ограничения; не более `100000`. |

Форматы результата:

- `table` — первая строка содержит заголовки колонок, далее строки со значениями через `" | "`. Пустой результат — заголовки и `(0 строк)`. При обрезке добавляется строка `... (обрезано: показаны первые N строк)`. Промежуточные временные таблицы пакета не выводятся.
- `csv` — заголовки и строки через запятую; значения с запятой или кавычкой экранируются. Для пакета каждый результат выводится отдельным блоком.
- `json` — объект `{"results":[{"index":1,"columns":[...],"rows":[...],"truncated":false}]}`. Ссылки представляются объектом `{"presentation":"...","uuid":"..."}`, даты — строкой ISO 8601, `NULL` — `null`, двоичные данные — строкой `<двоичные данные>`.

Параметры запроса:

```json
{
  "ДатаНачала": {"type": "date", "value": "2026-01-01T00:00:00"},
  "Номенклатура": {"type": "ref", "value": "Справочник.Номенклатура:d601b8de-6698-11ef-808d-fa163ec62d92"},
  "Маска": "%набор%",
  "Отбор": ["A", "B"]
}
```

Для параметра-ссылки можно также передать `{"metaType":"Справочник.Номенклатура","uuid":"..."}`. Массив параметров поддерживает вложенные типизированные значения.

Пример:

```json
{
  "name": "execute_query",
  "arguments": {
    "querytext": "ВЫБРАТЬ ПЕРВЫЕ 20 Т.Ссылка, Т.Наименование ИЗ Справочник.Номенклатура КАК Т ГДЕ Т.Наименование ПОДОБНО &Маска УПОРЯДОЧИТЬ ПО Т.Наименование",
    "parameters": {"Маска": "%набор%"},
    "format": "json",
    "maxRows": 20
  }
}
```

По умолчанию результат ограничен 1000 строками. Для полной выборки передайте `maxRows: 0`.

### `get_object`

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|---|---|---|
| `type` | string | да | — | Полное имя объекта метаданных, например `Справочник.Номенклатура` или `Документ.ЗаказКлиента`. |
| `uuid` | string | да | — | UUID ссылки в формате `00000000-0000-0000-0000-000000000000`. |
| `fields` | array of string | нет | все стандартные реквизиты и реквизиты | Имена полей объекта для вывода. Табличные части в `fields` не входят. |
| `includeTabularSections` | boolean | нет | `false` | Включать табличные части объекта. |
| `maxTabularRows` | number | нет | `100` | Максимум строк каждой табличной части, 1–1000. |

`get_object` работает для ссылочных объектов: справочников, документов, планов видов характеристик, планов счетов, планов видов расчёта, планов обмена, бизнес-процессов и задач. Регистры и константы не имеют ссылки, поэтому для них инструмент не применяется — используйте `execute_query`.

Результат — заголовок с полным именем и UUID, затем поля `Имя: значение`, затем, при `includeTabularSections: true`, табличные части в виде текстовых таблиц.

Пример:

```json
{
  "name": "get_object",
  "arguments": {
    "type": "Справочник.Номенклатура",
    "uuid": "d601b8de-6698-11ef-808d-fa163ec62d92",
    "fields": ["Наименование", "Артикул"],
    "includeTabularSections": true,
    "maxTabularRows": 20
  }
}
```

### `find_references`

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|---|---|---|---|---|
| `type` | string | да | — | Полное имя объекта метаданных, например `Справочник.Номенклатура`. |
| `uuid` | string | да | — | UUID ссылки. |
| `maxTables` | number | нет | `50` | Максимум проверяемых полей (таблица + поле), не более `500`. |

Инструмент проверяет стандартные реквизиты, реквизиты, измерения, ресурсы и табличные части объектов метаданных, а также константы. Сначала проверяются табличные части документов, затем документы и регистры, затем остальные объекты. Для каждого подходящего поля выполняется запрос `КОЛИЧЕСТВО(*)`; в результат попадают только поля с ненулевым количеством ссылок.

Ограничения:

- не проверяются субконто бухгалтерских регистров;
- проверяется не более `maxTables` полей; если подходящих полей больше, в результате будет указано, сколько проверено, и предложение увеличить `maxTables`;
- на больших базах запрос с сотнями `КОЛИЧЕСТВО(*)` может выполняться заметное время; начинайте с меньшего `maxTables`.

Пример:

```json
{
  "name": "find_references",
  "arguments": {
    "type": "Справочник.Номенклатура",
    "uuid": "d601b8de-6698-11ef-808d-fa163ec62d92",
    "maxTables": 500
  }
}
```

Пример результата:

```text
Ссылки на Справочник.Номенклатура d601b8de-6698-11ef-808d-fa163ec62d92:
Документ.РасходнаяНакладная.Запасы.Номенклатура: 50
РегистрНакопления.Запасы.Номенклатура: 505
Проверено полей: 500 из 747.
Проверены не все поля; увеличьте maxTables, чтобы охватить остальные.
```

### `get_configuration_info`

Параметров нет. Возвращает имя конфигурации, синоним, версию, режим совместимости, вариант встроенного языка, версию платформы и текущего пользователя информационной базы.

```json
{
  "name": "get_configuration_info",
  "arguments": {}
}
```

### `check_rights`

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `type` | string | да | Полное имя объекта метаданных, например `Справочник.Номенклатура`. |
| `right` | string | да | `read`, `insert`, `update`, `delete`, `post` или `view`. |

Инструмент проверяет право текущего пользователя на объект метаданных и возвращает `разрешено` или `запрещено`. Он не выдаёт права и не меняет данные. Право `post` применимо только к документам; для других объектов платформа может вернуть ошибку о неприменимости права.

```json
{
  "name": "check_rights",
  "arguments": {
    "type": "Справочник.Номенклатура",
    "right": "read"
  }
}
```

### `read_event_log`

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `dateFrom` | string | — | Начало периода: `ГГГГ-ММ-ДД` или `ГГГГ-ММ-ДДTЧЧ:ММ:СС` в локальном времени сервера. |
| `dateTo` | string | текущий момент | Окончание периода. Если указана только дата, включается весь день. |
| `errorsOnly` | boolean | `false` | Только ошибки (эквивалентно `levels = ["Ошибка"]`). |
| `levels` | array of string | — | Уровни: `Информация`, `Предупреждение`, `Ошибка`, `Примечание`. |
| `events` | array of string | — | Имена событий, например `_$Session$_.Start`, `_$PerformError$_`. |
| `users` | array of string | — | Имена пользователей информационной базы. |
| `computers` | array of string | — | Имена компьютеров. |
| `metadata` | array of string | — | Полные имена объектов метаданных, например `Документ.РасходнаяНакладная`. |
| `comment` | string | — | Точный текст комментария события. |
| `limit` | number | `100` | Максимальное количество событий, 1–1000. |
| `order` | string | `desc` | Порядок вывода: `desc` — от новых к старым, `asc` — от старых к новым. |

Если период не задан, читаются последние события: окно автоматически расширяется (1 день → 7 → 30 → 365 → весь журнал), пока не наберётся `limit` или не будет прочитан весь журнал.

Результат — заголовок с количеством событий и периодом, строка формата и события построчно:

```text
Журнал регистрации. Событий: 2. за период 2026-10-21 14:38:24 - 2026-10-22 14:38:24.
Формат: дата | уровень | событие | пользователь | компьютер | метаданные | данные | комментарий | транзакция
2026-10-22 14:00:39 | Ошибка | _$Session$_.ExternalDataProcessorConnectError (...) | admin | PC-01 | - | - | ... | Нет транзакции
```

Пример:

```json
{
  "name": "read_event_log",
  "arguments": {
    "errorsOnly": true,
    "dateFrom": "2026-10-01",
    "limit": 50
  }
}
```

## Как это работает

`MCP_Сервер` при старте обходит корневые подсистемы, в имени которых встречается `mcp_MCPСервер`, находит в них подсистему `mcp_КонтейнерыИнструментов` и вызывает у каждой обработки из её состава методы:

- `ДобавитьИнструменты(ТаблицаИнструментов)` — объявляет инструменты и JSON-схемы параметров;
- `ВыполнитьИнструмент(ИмяИнструмента, Аргументы)` — выполняет инструмент и возвращает текст.

Эти методы реализованы в `ManagerModule.bsl` каждой обработки. Схема параметров строится локально: общие модули расширения `MCP_Сервер` недоступны из другого расширения.

## Сборка из исходников

Загрузите XML-исходники в расширение информационной базы и выгрузите `.cfe`:

```bat
"C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" DESIGNER /S "<сервер>/<база>" /N <пользователь> /P <пароль> ^
  /LoadConfigFromFiles "<путь к репозиторию>" -Format Hierarchical -Extension 1C_MCP_Data

"C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" DESIGNER /S "<сервер>/<база>" /N <пользователь> /P <пароль> ^
  /UpdateDBCfg -Dynamic- -WarningsAsErrors -Extension 1C_MCP_Data

"C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" DESIGNER /S "<сервер>/<база>" /N <пользователь> /P <пароль> ^
  /DumpCfg "<путь к репозиторию>\build\1C_MCP_Data.cfe" -Extension 1C_MCP_Data
```

Перед применением полезно выполнить `/CheckModules -Extension 1C_MCP_Data`, `/CheckConfig -Extension 1C_MCP_Data` и `/CheckCanApplyConfigurationExtensions -Extension 1C_MCP_Data`.

## Безопасность

- Все инструменты только читают данные. `check_rights` не выдаёт права, а только проверяет их.
- `execute_query` не ограничивает текст запроса: доступны любые данные, которые разрешены пользователю информационной базы. Не публикуйте MCP-сервер под пользователем с избыточными правами.
- `get_object`, `find_references` и `get_configuration_info` также работают в правах пользователя информационной базы. `get_object` может вернуть значения реквизитов, `find_references` — только количество ссылок по полям, `get_configuration_info` — имя и версию конфигурации и текущего пользователя.
- `find_references` выполняет запросы `КОЛИЧЕСТВО(*)` по проверяемым полям. На больших базах ограничивайте `maxTables`.
- `read_event_log` показывает журнал регистрации, в том числе пользователей, компьютеры, данные и комментарии событий. Выдавайте право «Журнал регистрации» только тем пользователям, которым оно действительно нужно.
- Роли расширения управляют только видимостью инструментов; фактический доступ к данным и журналу определяется правами пользователя ИБ.

## Ограничения

- Имена расширения и его объектов начинаются с цифры (`1C_MCP_Data`, `1C_MCP_Data_...`). Платформа такие имена принимает, но `cfe-validate` и аналогичные проверки сообщают, что имя не является допустимым идентификатором 1С.
- `execute_query` по умолчанию ограничивает каждый результат 1000 строками (`maxRows`). Для полной выборки передайте `maxRows: 0`; максимум — 100000.
- `get_object` работает только для ссылочных объектов. Регистры и константы не имеют ссылки; для них используйте `execute_query`. Табличные части выводятся отдельно и не входят в `fields`.
- `find_references` проверяет не более `maxTables` полей (по умолчанию 50, максимум 500) и не проверяет субконто бухгалтерских регистров. Если в результате указано, что проверены не все поля, увеличьте `maxTables`.
- `find_references` не ищет ссылки в данных, не описанных метаданными (например, в настройках, отчётах, внешних файлах), и не заменяет полнотекстовый поиск.
- `read_event_log` работает только при наличии права `EventLog` в основной конфигурации; роли расширения не могут его предоставить.
- `limit = 0` в `read_event_log` из-за `ЗначениеЗаполнено(0)` трактуется как «параметр не задан» и заменяется значением по умолчанию 100.
- Контракт контейнеров (`ДобавитьИнструменты`, `ВыполнитьИнструмент`, подсистемы `mcp_MCPСервер` / `mcp_КонтейнерыИнструментов`) принадлежит `MCP_Сервер`. При несовместимом изменении сервера расширение потребует обновления.
