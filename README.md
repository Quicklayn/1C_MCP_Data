Расширение добавляет к [`MCP_Сервер`](https://github.com/vladimir-kharin/1c_mcp) инструменты доступа к данным информационной базы. Транспорт и протокол MCP реализует сервер; расширение только регистрирует контейнеры в подсистеме `mcp_КонтейнерыИнструментов`.

> Репозиторий и папка называются `1c_data_mcp`; имя самого расширения в 1С остаётся `1C_MCP_Data`, и его объекты (`1C_MCP_Data_ИнструментЗапросы`, роли, подсистема) сохраняют этот префикс.

> **Только чтение.** Записи, проведения и выполнения произвольного кода 1С в расширении нет.

## Инструменты

| | Инструмент | Назначение |
|:--:|---|---|
| 🔎 | **`execute_query`** | Запросы на языке 1С: `table`, `csv`, `json`, параметры, ограничение строк |
| 📦 | **`get_object`** | Объект по ссылке: реквизиты и табличные части |
| 🔗 | **`find_references`** | Где используется объект: поля со ссылками и количество |
| 🏷️ | **`get_configuration_info`** | Имя и версия конфигурации, платформа, пользователь |
| 🔐 | **`check_rights`** | Право пользователя на объект метаданных |
| 📜 | **`read_event_log`** | Журнал регистрации: события, ошибки, период |

## Установка

1. Скачайте [`build/1C_MCP_Data.cfe`](build/1C_MCP_Data.cfe).
2. В Конфигураторе: **Расширения конфигурации → Добавить → Применить**.
3. Назначьте роли пользователю публикации:
   - `1C_MCP_Data_ПраваИнструментЗапросы` — все инструменты данных;
   - `1C_MCP_Data_ПраваИнструментЖурналРегистрации` — `read_event_log`.
4. Проверьте `tools/list`: должно быть **6 инструментов**.

**Требования:** 1С:Предприятие 8.3.20+ (управляемое приложение) и [`MCP_Сервер`](https://github.com/vladimir-kharin/1c_mcp) 1.9.1+. Для журнала регистрации нужно право `EventLog` в основной конфигурации.

## Примеры

**Запрос с параметром**

```json
{
  "name": "execute_query",
  "arguments": {
    "querytext": "ВЫБРАТЬ ПЕРВЫЕ 20 Т.Ссылка, Т.Наименование ИЗ Справочник.Номенклатура КАК Т ГДЕ Т.Наименование ПОДОБНО &Маска",
    "parameters": { "Маска": "%набор%" },
    "format": "json",
    "maxRows": 20
  }
}
```

**Поиск ссылок на объект**

```json
{
  "name": "find_references",
  "arguments": {
    "type": "Справочник.Номенклатура",
    "uuid": "d601b8de-6698-11ef-808d-fa163ec62d92",
    "maxTables": 500
  }
}
```

## Безопасность

- Все инструменты только читают данные; `check_rights` ничего не выдаёт.
- Доступ к данным определяется правами пользователя ИБ. `execute_query` не ограничивает текст запроса — не публикуйте MCP под избыточными правами.
- `find_references` выполняет `КОЛИЧЕСТВО(*)` по проверяемым полям — на больших базах уменьшайте `maxTables`.
- Журнал регистрации содержит пользователей, компьютеры и данные; выдавайте `EventLog` только тем, кому он нужен.

## Ограничения

- `execute_query` — по умолчанию 1000 строк; `maxRows: 0` — без лимита (до 100 000).
- `get_object` — только ссылочные объекты; регистры и константы читайте через `execute_query`.
- `find_references` — до `maxTables` полей (по умолчанию 50, максимум 500); субконто бухгалтерских регистров не проверяются.
- `read_event_log` — только при праве `EventLog`; `limit = 0` трактуется как 100.

<summary><b>Справочник по инструментам</b></summary>

### `execute_query`

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `querytext` | string | — | Запрос или пакет запросов через `;`. |
| `parameters` | object | — | Значения параметров без `&`: строка, число, булево, `null`, массив или `{"type":"date","value":"..."}`, `{"type":"ref","value":"Справочник.Номенклатура:<uuid>"}`. |
| `format` | string | `table` | `table`, `csv` или `json`. |
| `maxRows` | number | `1000` | Строк на один результат; `0` — без ограничения, максимум `100000`. |

В `json` ссылки выводятся как `{"presentation":"...","uuid":"..."}`, даты — ISO 8601, `NULL` — `null`, двоичные данные — `<двоичные данные>`.

### `get_object`

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `type` | string | — | Полное имя, например `Справочник.Номенклатура`. |
| `uuid` | string | — | UUID ссылки. |
| `fields` | array | все реквизиты | Поля объекта; табличные части сюда не входят. |
| `includeTabularSections` | boolean | `false` | Выводить табличные части. |
| `maxTabularRows` | number | `100` | Строк каждой табличной части, 1–1000. |

Работает для справочников, документов, планов видов характеристик, планов счетов, планов видов расчёта, планов обмена, бизнес-процессов и задач.

### `find_references`

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `type` | string | — | Полное имя объекта метаданных. |
| `uuid` | string | — | UUID ссылки. |
| `maxTables` | number | `50` | Максимум проверяемых полей, до `500`. |

Проверяются реквизиты, измерения, ресурсы, стандартные реквизиты, табличные части и константы. Сначала — табличные части документов, затем документы и регистры, затем остальные объекты. Возвращаются только поля с ненулевым количеством ссылок.

### `get_configuration_info`

Без параметров. Возвращает имя, синоним, версию и режим совместимости конфигурации, вариант встроенного языка, версию платформы и текущего пользователя.

### `check_rights`

| Параметр | Тип | Описание |
|---|---|---|
| `type` | string | Полное имя объекта метаданных. |
| `right` | string | `read`, `insert`, `update`, `delete`, `post` или `view`. |

`post` применимо только к документам. Инструмент не выдаёт права, а только проверяет их.

### `read_event_log`

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `dateFrom` | string | — | Начало периода: `ГГГГ-ММ-ДД` или `ГГГГ-ММ-ДДTЧЧ:ММ:СС`. |
| `dateTo` | string | сейчас | Окончание периода; только дата — весь день. |
| `errorsOnly` | boolean | `false` | Только ошибки. |
| `levels` | array | — | `Информация`, `Предупреждение`, `Ошибка`, `Примечание`. |
| `events` | array | — | Имена событий. |
| `users` | array | — | Пользователи ИБ. |
| `computers` | array | — | Компьютеры. |
| `metadata` | array | — | Полные имена объектов метаданных. |
| `comment` | string | — | Точный текст комментария. |
| `limit` | number | `100` | Количество событий, 1–1000. |
| `order` | string | `desc` | `desc` или `asc`. |

Если период не задан, окно автоматически расширяется (1 день → 7 → 30 → 365 → весь журнал), пока не наберётся `limit`.
