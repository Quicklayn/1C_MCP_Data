# 1C_MCP_Data

Расширение 1С:Предприятие 8.3, которое добавляет MCP-серверу [`MCP_Сервер`](https://github.com/vladimir-kharin/1c_mcp) инструменты доступа к данным информационной базы: выполнение запросов на языке запросов 1С и чтение журнала регистрации.

Расширение не реализует транспорт и протокол MCP. Оно регистрирует обработки-контейнеры в подсистеме `mcp_КонтейнерыИнструментов`, которые сервер `MCP_Сервер` обнаруживает и публикует как MCP-инструменты.

## Возможности

| Инструмент | Назначение |
|---|---|
| `execute_query` | Выполняет запрос (в том числе пакет запросов) на языке запросов 1С и возвращает результат текстовой таблицей. |
| `read_event_log` | Читает журнал регистрации: последние события, только ошибки, период, события, пользователи, компьютеры, объекты метаданных. |

Инструменты не выполняют произвольный код 1С: `execute_query` работает только на языке запросов, `read_event_log` — только с журналом регистрации.

## Требования

- 1С:Предприятие 8.3.20 или новее (режим совместимости расширения — `Version8_3_20`), управляемое приложение.
- Расширение `MCP_Сервер` версии 1.9.1 или новее (проверено на 1.9.1) с поддержкой поиска корневых подсистем по имени `mcp_MCPСервер`.
- Опубликованный HTTP-сервис MCP (по умолчанию `/hs/mcp`) — настраивается на стороне `MCP_Сервер`.
- Для `read_event_log` — право «Журнал регистрации» (`EventLog`) у пользователя информационной базы. Право выдаётся только основной конфигурацией; роли расширения не могут его предоставить.

## Установка

1. Скачайте готовое расширение `build/1C_MCP_Data.cfe`.
2. В Конфигураторе откройте «Расширения конфигурации», добавьте файл и примените его к базе.
3. Убедитесь, что расширение `MCP_Сервер` установлено и его HTTP-сервис доступен.
4. Назначьте пользователю публикации роли:
   - `1C_MCP_Data_ПраваИнструментЗапросы` — доступ к `execute_query`;
   - `1C_MCP_Data_ПраваИнструментЖурналРегистрации` — доступ к `read_event_log`.

   Пользователь с полными правами (например, `admin` в тестовой базе) видит инструменты без назначения ролей.
5. Проверьте `tools/list` MCP-сервера: в списке должны появиться `execute_query` и `read_event_log`.

Роли расширения дают только право `Use` на обработки-контейнеры. Доступ к данным определяется правами пользователя информационной базы.

## Инструменты

### `execute_query`

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `querytext` | string | да | Текст запроса на языке запросов 1С. Допускается пакет запросов, разделённых `;`. |

Результат — текстовая таблица: первая строка содержит заголовки колонок, далее строки со значениями через `" | "`. Пустой результат — заголовки и `(0 строк)`. Промежуточные временные таблицы пакета не выводятся.

Пример:

```json
{
  "name": "execute_query",
  "arguments": {
    "querytext": "ВЫБРАТЬ ПЕРВЫЕ 10 Ссылка, Номер, Дата ИЗ Документ.РасходнаяНакладная УПОРЯДОЧИТЬ ПО Дата УБЫВ"
  }
}
```

### `read_event_log`

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `dateFrom` | string | — | Начало периода: `ГГГГ-ММ-ДД` или `ГГГГ-ММ-ДДTЧЧ:ММ:СС` в локальном времени сервера. |
| `dateTo` | string | текущий момент | Окончание периода. Если указана только дата, включается весь день. |
| `errorsOnly` | boolean | `false` | Только ошибки (эквивалентно `levels = ["Ошибка"]`). |
| `levels` | array of string | — | Уровни: `Информация`, `Предупреждение`, `Ошибка`, `Примечание`. |
| `events` | array of string | — | Имена событий, например `_$Session$_.Start`, `_$PerformError$_`. |
| `users` | array of string | — | Имена пользователей информационной базы. |
| `computers` | array of string | — | Имена компьютеров. |
| `metadata` | array of string | — | Полные имена объектов метаданных, например `Документ.РасходнаяНакладная`. |
| `comment` | string | — | Точный текст комментария события. |
| `limit` | number | `100` | Максимальное количество событий, 1–1000. |
| `order` | string | `desc` | Порядок вывода: `desc` — от новых к старым, `asc` — от старых к новым. |

Если период не задан, читаются последние события: окно автоматически расширяется (1 день → 7 → 30 → 365 → весь журнал), пока не наберётся `limit` или не будет прочитан весь журнал.

Результат — заголовок с количеством событий и периодом, строка формата и события построчно:

```text
Журнал регистрации. Событий: 2. за период 2026-10-21 14:38:24 - 2026-10-22 14:38:24.
Формат: дата | уровень | событие | пользователь | компьютер | метаданные | данные | комментарий | транзакция
2026-10-22 14:00:39 | Ошибка | _$Session$_.ExternalDataProcessorConnectError (...) | admin | PC-01 | - | - | ... | Нет транзакции
```

Пример:

```json
{
  "name": "read_event_log",
  "arguments": {
    "errorsOnly": true,
    "dateFrom": "2026-10-01",
    "limit": 50
  }
}
```

## Как это работает

`MCP_Сервер` при старте обходит корневые подсистемы, в имени которых встречается `mcp_MCPСервер`, находит в них подсистему `mcp_КонтейнерыИнструментов` и вызывает у каждой обработки из её состава методы:

- `ДобавитьИнструменты(ТаблицаИнструментов)` — объявляет инструменты и JSON-схемы параметров;
- `ВыполнитьИнструмент(ИмяИнструмента, Аргументы)` — выполняет инструмент и возвращает текст.

Эти методы реализованы в `ManagerModule.bsl` каждой обработки. Схема параметров строится локально: общие модули расширения `MCP_Сервер` недоступны из другого расширения.

## Сборка из исходников

Загрузите XML-исходники в расширение информационной базы и выгрузите `.cfe`:

```bat
"C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" DESIGNER /S "<сервер>/<база>" /N <пользователь> /P <пароль> ^
  /LoadConfigFromFiles "<путь к репозиторию>" -Format Hierarchical -Extension 1C_MCP_Data

"C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" DESIGNER /S "<сервер>/<база>" /N <пользователь> /P <пароль> ^
  /UpdateDBCfg -Extension 1C_MCP_Data

"C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" DESIGNER /S "<сервер>/<база>" /N <пользователь> /P <пароль> ^
  /DumpCfg "<путь к репозиторию>\build\1C_MCP_Data.cfe" -Extension 1C_MCP_Data
```

Перед применением полезно выполнить `/CheckModules -Extension 1C_MCP_Data`, `/CheckConfig -Extension 1C_MCP_Data` и `/CheckCanApplyConfigurationExtensions -Extension 1C_MCP_Data`.

## Безопасность

- `execute_query` не ограничивает текст запроса: доступны любые данные, которые разрешены пользователю информационной базы. Не публикуйте MCP-сервер под пользователем с избыточными правами.
- `read_event_log` показывает журнал регистрации, в том числе пользователей, компьютеры, данные и комментарии событий. Выдавайте право «Журнал регистрации» только тем пользователям, которым оно действительно нужно.
- Роли расширения управляют только видимостью инструментов; фактический доступ к данным и журналу определяется правами пользователя ИБ.

## Ограничения

- Имена расширения и его объектов начинаются с цифры (`1C_MCP_Data`, `1C_MCP_Data_...`). Платформа такие имена принимает, но `cfe-validate` и аналогичные проверки сообщают, что имя не является допустимым идентификатором 1С.
- `limit = 0` из-за `ЗначениеЗаполнено(0)` трактуется как «параметр не задан» и заменяется значением по умолчанию 100.
- `read_event_log` работает только при наличии права `EventLog` в основной конфигурации; роли расширения не могут его предоставить.
- Контракт контейнеров (`ДобавитьИнструменты`, `ВыполнитьИнструмент`, подсистемы `mcp_MCPСервер` / `mcp_КонтейнерыИнструментов`) принадлежит `MCP_Сервер`. При несовместимом изменении сервера расширение потребует обновления.
